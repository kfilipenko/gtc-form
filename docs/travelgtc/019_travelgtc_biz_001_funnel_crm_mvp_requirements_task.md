# TRAVELGTC-BIZ-001 - Funnel And CRM MVP Requirements

- Project: TravelGTC
- Owner: Project Owner
- Source architecture: `docs/travelgtc/018_travelgtc_arch_001_funnel_crm_agent_platform_spec.md`
- Document type: Task
- Version: 0.1
- Date: 2026-07-09
- Status: Implemented

## 1. Purpose

Convert the approved TravelGTC architecture into actionable MVP requirements for:

1. a single strong public funnel;
2. own lead capture API;
3. own lead and CRM database model;
4. first CRM workspace;
5. AI agent boundaries;
6. consent and compliance minimums;
7. acceptance tests for the first implementation stage.

## 2. Strategic Constraint

The MVP must not sell "network technology" as the first product.

The MVP must start from user needs:

1. travel more;
2. join interesting trips/events;
3. create a route;
4. gather people;
5. understand club and partner opportunities without pressure.

## 3. Scope

This task includes specifying:

1. public funnel structure;
2. role-selection logic;
3. form fields and validation;
4. CRM stages and lead transitions;
5. first database tables and fields;
6. first API endpoint contracts;
7. first CRM screens;
8. AI agent instruction boundaries;
9. privacy/consent minimum text;
10. MVP acceptance tests.

## 4. Out Of Scope

This task does not include:

1. backend implementation;
2. frontend redesign implementation;
3. official third-party platform integration;
4. payment, booking or membership purchase logic;
5. automated outbound messaging without human approval;
6. production collection of real personal data before privacy/consent pages are approved.

## 5. Acceptance Criteria

The task is complete when:

1. a requirements specification is created;
2. the specification includes exact funnel fields;
3. the specification includes database table requirements;
4. the specification includes API contracts;
5. the specification includes CRM screen requirements;
6. the specification includes AI agent boundaries;
7. documentation register and memory are updated;
8. repository changes are committed.
